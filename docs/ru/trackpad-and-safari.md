# Жесты трекпада и Safari

Это про удобство, а не про работоспособность — ничего из перечисленного для работы машины не нужно. В
репозитории оно потому, что первая часть попутно выяснила кое-что полезное про трекпад на хакинтоше, и потому
что оба ответа искались дольше, чем следовало.

## Тап четырьмя пальцами как средний клик

В macOS нет средней кнопки мыши, поэтому браузеры теряют две привычные для Linux и Windows вещи: средний
клик по ссылке открывает её в фоновой вкладке, а средний клик по вкладке закрывает её. Safari **умеет** и то
и другое — просто нечем нажать.

Встроенного жеста ни для одного из этих действий **нет**, и добавить его ни настройкой Safari, ни расширением
нельзя: расширения Safari не имеют доступа к интерфейсу самого браузера.

Работает эмуляция средней кнопки — и тогда один жест закрывает оба действия, каждое в своём контексте.

### Почему трекпад это вообще может

Стоит сказать отдельно, потому что на хакинтоше это неочевидно. I²C-трекпад 9500 идёт через
`VoodooI2C` 2.9.1 → `VoodooI2CHID` → `VoodooInput` 1.1.7, и VoodooInput подаёт его штатному
`AppleMultitouchDriver` как **Magic Trackpad 2**:

```bash
ioreg -rc AppleMultitouchDevice -w0 | grep -E '"Product"|"MT Built-In"'
```

```
"Product" = "Magic Trackpad 2"
"MT Built-In" = Yes
```

Именно поэтому сторонние утилиты жестов здесь работают: они читают пальцы через приватный фреймворк
многокасания, а для того фреймворка это настоящий трекпад Apple.

Число пальцев тоже не ограничение:

```bash
ioreg -l -w0 -r -c VoodooI2CMultitouchHIDEventDriver | grep -o '"Transducer Count"=[0-9]*'
```

```
"Transducer Count"=5
```

Пять одновременных касаний, и `TrackpadFourFingerGestures = Yes`.

### Почему четыре пальца, а не три

Три пальца — обычный выбор, и на этой машине он неверный, по двум конкретным причинам:

```bash
defaults read com.apple.AppleMultitouchTrackpad TrackpadThreeFingerDrag        # 1
defaults read com.apple.AppleMultitouchTrackpad TrackpadThreeFingerTapGesture  # 2 = Поиск
```

- **Перетаскивание тремя пальцами включено**, и оно по-настоящему полезно — так выделяют текст и двигают окна
  без нажатия. Утилита на трёхпальцевый тап с ним конкурирует и срабатывает невпопад.
- **Тап тремя пальцами уже занят** — «Поиск и распознавание данных» (`2`).

Четыре пальца свободны. macOS занимает четырёхпальцевые *свайпы* и *щипок*, но **настройки тапа четырьмя
пальцами не существует вовсе** — такого ключа просто нет:

```bash
for k in TrackpadFourFingerHorizSwipeGesture TrackpadFourFingerVertSwipeGesture \
         TrackpadFourFingerPinchGesture TrackpadFiveFingerPinchGesture; do
  echo "$k = $(defaults read com.apple.AppleMultitouchTrackpad $k)"
done
```

Все четыре возвращают `2`; тап четырьмя пальцами не читает никто. Значит жест можно забрать себе, ничего не
отдав, а трёхпальцевые остаются точно как были.

### Как настроить

Брать стоит [MiddleClick](https://github.com/artginzburg/MiddleClick) (GPL-3.0) — именно потому, что число
пальцев у него настраивается. Здесь использована версия 3.3.0.

```bash
brew install --cask middleclick        # либо скачать .zip из релизов на GitHub
defaults write art.ginzburg.MiddleClick fingers -int 4
```

`fingers` принимает 2, 4, 5 и значение по умолчанию 3.

Дальше выдать ему **Универсальный доступ** в «Системные настройки → Конфиденциальность и безопасность» и
включить *запуск при входе* в его меню в строке меню — без этого после перезагрузки жеста не будет.

Проверить, что разрешение действительно выдано, а не верить галочке:

```bash
sqlite3 /Library/Application\ Support/com.apple.TCC/TCC.db \
  "select client,auth_value from access where service='kTCCServiceAccessibility'"
```

`2` — разрешено, `0` — запись есть, но доступ запрещён; именно это вы увидите, если запрос появился и его
закрыли.

Отдавайте себе отчёт, что даёте: «Универсальный доступ» позволяет программе видеть **все** события ввода.
Исходники открыты, релиз нотаризован (`Developer ID Application: Arthur Ginzburg (R2294BC6J8)`), и это
проверяется до установки:

```bash
spctl -a -vvv /Applications/MiddleClick.app
```

```
accepted
source=Notarized Developer ID
```

**Не снимайте атрибут карантина**, чтобы приложение запустилось. Нотаризованному он не нужен, а снятие
обнуляет ровно ту проверку, которая и сказала вам, что приложение — то, за что себя выдаёт.

### Что получается

Тап четырьмя пальцами по ссылке открывает её в фоновой вкладке, тап четырьмя пальцами по вкладке — закрывает.
Работает в Safari, Chrome и Firefox одинаково, потому что это настоящий средний клик, а не трюк для одного
браузера.

Если тап мажет, у утилиты два порога:

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `maxDistanceDelta` | 0.05 | насколько курсор может сместиться между касанием и отрывом |
| `maxTimeDelta` | 300 | максимальная длительность тапа, мс |

На эмулированном трекпаде чуть больший `maxTimeDelta` может помочь.

## Safari: восстанавливать прошлый сеанс при выходе

По умолчанию Safari открывается новым пустым окном, выбрасывая всё, что было открыто на момент выхода.
Меняет это настройка «Safari открывается с: Все окна из последнего сеанса» в «Настройки → Основные», либо:

```bash
defaults write com.apple.Safari AlwaysRestoreSessionAtLaunch -bool true
```

Стоит проверить и системный флаг — он управляет восстановлением окон для всех программ:

```bash
defaults read -g NSQuitAlwaysKeepsWindows
```

`1` означает, что окна восстанавливаются (галочка «Закрывать окна при завершении программы» в «Настройки →
Рабочий стол и Dock» **снята**). На этой машине он и так был `1`, не хватало только настройки со стороны
Safari.

Рядом и в быту нужнее:

| | |
|---|---|
| Вернуть последнюю закрытую вкладку | **⇧⌘T** |
| Список недавно закрытых | История → Недавно закрытые |
| Вернуть прошлый сеанс вручную | История → Открыть все окна из последнего сеанса |

Окна частного доступа не восстанавливаются никогда. Это by design, а не сломанная настройка.

## Safari: вкладки сбоку — возможно только наполовину

Спросили — отвечаем честно: **вертикальный список вкладок в Safari есть, а горизонтальную панель вкладок
скрыть нельзя.** Проверено на Safari 18.6.

`⌃⌘S` («Вид → Показать боковое меню») открывает панель, где вкладки текущего окна и группы вкладок
перечислены вертикально — с иконками, перетаскиванием и закрытием крестиком. Но это та же панель, что держит
закладки и список для чтения: панель, а не замена панели вкладок. `Вид → Скрыть панель вкладок` доступен
только при единственной вкладке, так что при нескольких вкладках вы получаете и боковую панель, и
горизонтальную полосу одновременно.

Чтобы она открывалась в каждом новом окне:

```bash
defaults write com.apple.Safari ShowSidebarInNewWindows -bool true
```

Две вещи, выясненные на практике:

- **Включите заодно компактные вкладки** («Настройки → Вкладки → Компактный»), иначе дублирование раздражает —
  верхняя полоса сожмётся почти до иконок.
- **Видимость боковой панели задавайте в самом интерфейсе Safari, а не через `defaults`.** Safari сам
  запоминает состояние панели при выходе, поэтому окно, оставленное с открытой панелью, запишет это состояние
  обратно и перебьёт правку снаружи. А вот `AlwaysRestoreSessionAtLaunch` из предыдущего раздела ложится в
  plist сразу, и его из командной строки менять безопасно.

Если нужны настоящие вертикальные вкладки **вместо** горизонтальных — Safari этого не умеет ни при какой
настройке. Нужен другой браузер: ближе всего для привыкшего к Safari — [Orion](https://browser.kagi.com/),
он на WebKit, нативный и умеет расширения Safari.
