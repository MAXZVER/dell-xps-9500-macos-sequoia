# Как включить низкочастотные динамики

В XPS 15 9500 четыре динамика: два твитера и два низкочастотных. На macOS из коробки работают только
твитеры — отсюда тонкое, «жестяное» звучание и жалобы, что басов нет вовсе.

Это чинится, и это не костыль: низкочастотные сидят на том же кодеке, их просто надо включить.

## В чём дело

Кодек — Realtek **ALC289**. Если снять его pin-конфигурацию:

| Узел | Pin config | Что это | Возможности |
|---|---|---|---|
| `0x14` | `0x90170110` | Fixed / Speaker | PresenceDetect, **OUT**, **EAPD** |
| `0x17` | `0x411111F0` | **не используется** | PresenceDetect, HeadphoneDrive, **OUT** |
| `0x1b` | `0x411111F0` | не используется | OUT, IN, EAPD |
| `0x21` | `0x01211020` | Jack / наушники | OUT, EAPD |

Узел `0x14` — твитеры. Узел **`0x17` — низкочастотные**, но прошивка Dell объявляет его незадействованным,
и macOS его не трогает. В Linux ровно та же беда, и там её
[лечат правкой pin-конфигурации](https://github.com/makeitmakesencethen/dell-xps-15-9500-linux-audio):
`0x17` переписывают с `0x411111f0` на `0x90170130`.

Отдельного усилителя нет. Один кодек, одно недостающее объявление вывода.

## Что не работает

**Инжект `PinConfigurations` через `DeviceProperties` ничего не даёт.** Выглядит логично — свойство есть в
реестре ввода-вывода, — но AppleHDA читает конфигурацию напрямую из кодека и наше значение игнорирует.
Проверено: после перезагрузки с этим свойством `0x17` по-прежнему возвращал `0x411111F0`.

**Смена раскладки AppleALC тоже не помогает.** В `Resources/ALC289/` лежат только описания графа DSP
(`layoutNN.xml`, `PlatformsNN.xml`), а `ConfigData` нет вовсе — то есть AppleALC для этого кодека
pin-конфигурацию не отправляет в принципе. Раскладки 13 и 93 обе сделаны под XPS 9500, и ни одна не
включает `0x17`.

## Что работает

Отправлять команды кодеку на живой системе утилитой **`alc-verb`** из
[исходников AppleALC](https://github.com/acidanthera/AppleALC/tree/master/alc-verb).

**1. Разрешить отправку команд.** Добавьте `alcverbs=1` в загрузочные аргументы.

**2. Собрать `alc-verb`** (нужны Command Line Tools):

```bash
mkdir -p /tmp/av && cd /tmp/av
curl -sLO https://raw.githubusercontent.com/acidanthera/AppleALC/master/alc-verb/main.c
curl -sLO https://raw.githubusercontent.com/acidanthera/AppleALC/master/alc-verb/hdaverb.h
curl -sLO https://raw.githubusercontent.com/acidanthera/AppleALC/master/AppleALC/UserKernelShared.h
clang -O2 -framework IOKit -framework CoreFoundation main.c -o alc-verb
sudo cp alc-verb /usr/local/bin/
```

**3. Сами команды:**

```bash
alc-verb 0x17 0x71c 0x30     # байт 0 pin config  ┐
alc-verb 0x17 0x71d 0x01     # байт 1             ├─ 0x90170130 = внутренний динамик
alc-verb 0x17 0x71e 0x17     # байт 2             │
alc-verb 0x17 0x71f 0x90     # байт 3             ┘
alc-verb 0x17 0x701 0x01     # выбор источника → ЦАП 0x03
alc-verb 0x17 0x707 0x40     # разрешить выход на пине
alc-verb 0x17 0x300 0xb000   # снять приглушение усилителя
```

**4. Закрепить** через [`scripts/woofer.sh`](../../scripts/woofer.sh) и
[`scripts/com.local.woofer.plist`](../../scripts/com.local.woofer.plist):

```bash
sudo cp scripts/woofer.sh /usr/local/bin/
sudo chmod 755 /usr/local/bin/woofer.sh
sudo cp scripts/com.local.woofer.plist /Library/LaunchDaemons/
sudo chown root:wheel /Library/LaunchDaemons/com.local.woofer.plist
sudo launchctl bootstrap system /Library/LaunchDaemons/com.local.woofer.plist
```

Демон дожидается запуска звука, применяет команды и повторяет их, если кодек сбросился — а это происходит
после пробуждения и при смене устройства вывода.

## Почему ЦАП 0x03 и почему демон

Узел `0x17` можно питать от ЦАП `0x02`, `0x03` или `0x06`. На `0x02` сидят твитеры.

`0x02` и `0x03` несут один и тот же поток, и **macOS двигает их громкость синхронно** — проверено:

```
громкость 30%:  0x02 = 0x30   0x03 = 0x30
громкость 90%:  0x02 = 0x53   0x03 = 0x53
```

Если посадить низкочастотные на `0x03`, их уровень можно держать *выше* твитеров на постоянную величину —
получается настоящий аппаратный подъём низов, который при этом следует за регулятором громкости. Разовая
правка усиления слетела бы при первом же его изменении, поэтому и нужен демон, который держит

```
усиление(0x03) = min( усиление(0x02) + OFFSET, CAP )
```

Обе величины — в начале `woofer.sh`. По умолчанию `OFFSET=16` (16 × 0,75 дБ ≈ +12 дБ) и `CAP=0x52`.

Усилители на пинах у этого кодека **только с приглушением** (`AMP-OUT cap = 0x80000000`), вся регулировка
громкости — на ЦАП. Не тратьте время на попытки выставить уровень самому `0x17`. У ЦАП 87 шагов по
0,75 дБ, максимум `0x57`.

## Измерения

Мерялось **внешним микрофоном** — Logitech C930e на штативе в 10 см от ноутбука, запись на отдельной машине
через ffmpeg, разбор фильтром Гёрцеля на частоте тона. Шум помещения во время замеров: −98,4 дБ RMS.

> **В предыдущей версии этого документа были другие цифры, снятые встроенным микрофоном ноутбука. Они
> оказались неверными и заменены.** Встроенный микрофон стоит в корпусе и ловит вибрацию через шасси, поэтому
> его показания сильно зависят от того, на чём стоит ноутбук, — и он придумывал искажения, которых нет.
> Характеризовать эти динамики встроенным микрофоном нельзя.

**Только твитеры:**

| Тон | Уровень | Искажения |
|---|---|---|
| 1 кГц | **−40,4 дБ** | 0,6 % |
| 200 Гц | **−127,5 дБ** | — (ниже уровня шума) |

На 200 Гц твитеры не выдают *ничего* — на 87 дБ ниже собственного уровня на 1 кГц и ниже шума помещения.
«Басов нет» — это буквальная констатация. На 1 кГц они при этом чистые: 0,6 % искажений.

**Только низкочастотные, 200 Гц, перебор усиления ЦАП:**

| Усиление ЦАП | Уровень | Искажения |
|---|---|---|
| `0x41` | −42,8 дБ | 1,1 % |
| `0x48` | **−29,4 дБ** | 2,4 % |
| `0x4e` | −29,3 дБ | 2,7 % |
| `0x52` | −29,0 дБ | 2,6 % |
| `0x55` | −29,5 дБ | 2,7 % |
| `0x57` (максимум) | −29,3 дБ | 2,8 % |

Отсюда два следствия. Против −127,5 дБ у твитеров низкочастотные дают −29 дБ на той же частоте — то есть
**примерно на 98 дБ больше на 200 Гц**. И уровень **насыщается уже на `0x48`**: всё, что выше, совпадает в
пределах погрешности, так что дальнейшее усиление здесь ничего не добавляет.

**Только низкочастотные, 120 Гц:**

| Усиление ЦАП | Уровень | Искажения |
|---|---|---|
| `0x4e` | −45,3 дБ | 14,2 % |
| `0x52` | −43,6 дБ | 9,2 % |
| `0x55` | −42,5 дБ | 12,2 % |
| `0x57` (максимум) | −39,9 дБ | **57,2 %** |

Ниже по частоте запас по уровню ещё есть, но там же и обрыв: на максимуме кодека третья гармоника доходит до
−44,7 дБ, а искажения до 57 %. Это динамик уходит в отбой, и на слух это дребезжание.

`CAP=0x52` вытекает из этих двух таблиц: на 200 Гц выход к этому моменту уже насыщен, а на 120 Гц это точка с
наименьшими искажениями из измеренных.

## Оговорки

- Динамики маленькие. Это даёт реальную нижнюю середину в районе 120–250 Гц, но не глубокий бас. На 70 Гц
  намерять не удалось ничего.
- `alcverbs=1` должен остаться в boot-args, иначе демон молча не сделает ничего.
- Демон опрашивает кодек раз в 3 секунды — это дёшево, но означает небольшую задержку после изменения
  громкости.
- Ручная отправка команд усиления может рассинхронизировать представление macOS о громкости с кодеком:
  регулятор показывает 85 %, а ЦАП стоит на нуле. Лечится любым движением регулятора. Возникает только после
  ручных экспериментов, в обычной работе — нет.

## Утилиты для измерений

`tools/rec.swift` пишет звук со входа по умолчанию в WAV; `tools/measure-thd.py` показывает уровень основного
тона и его второй и третьей гармоник.

**Лучше внешний микрофон на второй машине.** Встроенный здесь непригоден по причинам выше. Схема, которой
получены цифры этого документа: тоновые файлы на маке проигрываются через `afplay` по SSH, запись на машине с
Windows командой

```
ffmpeg -f dshow -i audio="Microphone (...)" -t 5 -ac 1 -ar 48000 -y out.wav
```

и разбор через `tools/measure-thd.py`. Ноутбук и микрофон между прогонами не двигать, иначе абсолютные уровни
несопоставимы.

Если всё же берёте встроенный микрофон: **процесс, запущенный через SSH, до него не доберётся.** macOS
откажет молча и отдаст файл из одних нулей, не показав запроса. Запускайте из графической сессии —
`open -a Terminal /путь/к/скрипту.command` вызывает запрос разрешения как положено.
