# Как включить низкочастотные динамики

В XPS 15 9500 четыре динамика: два твитера и два низкочастотных. На macOS из коробки работают только
твитеры — отсюда тонкое, «жестяное» звучание и жалобы, что басов нет вовсе.

Это чинится, и это не костыль: низкочастотные сидят на том же кодеке, их просто надо включить.

## В чём дело

Кодек — Realtek **ALC289**. Если снять его pin-конфигурацию:

| Узел | Pin config | Что это | Возможности |
|---|---|---|---|
| `0x14` | `0x90170110` | Fixed / Speaker | PresenceDetect, **OUT**, **EAPD** |
| `0x17` | `0x411111F0` | **не используется** | PresenceDetect, HeadphoneDrive, **OUT** |
| `0x1b` | `0x411111F0` | не используется | OUT, IN, EAPD |
| `0x21` | `0x01211020` | Jack / наушники | OUT, EAPD |

Узел `0x14` — твитеры. Узел **`0x17` — низкочастотные**, но прошивка Dell объявляет его незадействованным,
и macOS его не трогает. В Linux ровно та же беда, и там её
[лечат правкой pin-конфигурации](https://github.com/makeitmakesencethen/dell-xps-15-9500-linux-audio):
`0x17` переписывают с `0x411111f0` на `0x90170130`.

Отдельного усилителя нет. Один кодек, одно недостающее объявление вывода.

## Что не работает

**Инжект `PinConfigurations` через `DeviceProperties` ничего не даёт.** Выглядит логично — свойство есть в
реестре ввода-вывода, — но AppleHDA читает конфигурацию напрямую из кодека и наше значение игнорирует.
Проверено: после перезагрузки с этим свойством `0x17` по-прежнему возвращал `0x411111F0`.

**Смена раскладки AppleALC тоже не помогает.** В `Resources/ALC289/` лежат только описания графа DSP
(`layoutNN.xml`, `PlatformsNN.xml`), а `ConfigData` нет вовсе — то есть AppleALC для этого кодека
pin-конфигурацию не отправляет в принципе. Раскладки 13 и 93 обе сделаны под XPS 9500, и ни одна не
включает `0x17`.

## Что работает

Отправлять команды кодеку на живой системе утилитой **`alc-verb`** из
[исходников AppleALC](https://github.com/acidanthera/AppleALC/tree/master/alc-verb).

**1. Разрешить отправку команд.** Добавьте `alcverbs=1` в загрузочные аргументы.

**2. Собрать `alc-verb`** (нужны Command Line Tools):

```bash
mkdir -p /tmp/av && cd /tmp/av
curl -sLO https://raw.githubusercontent.com/acidanthera/AppleALC/master/alc-verb/main.c
curl -sLO https://raw.githubusercontent.com/acidanthera/AppleALC/master/alc-verb/hdaverb.h
curl -sLO https://raw.githubusercontent.com/acidanthera/AppleALC/master/AppleALC/UserKernelShared.h
clang -O2 -framework IOKit -framework CoreFoundation main.c -o alc-verb
sudo cp alc-verb /usr/local/bin/
```

**3. Сами команды:**

```bash
alc-verb 0x17 0x71c 0x30     # байт 0 pin config  ┐
alc-verb 0x17 0x71d 0x01     # байт 1             ├─ 0x90170130 = внутренний динамик
alc-verb 0x17 0x71e 0x17     # байт 2             │
alc-verb 0x17 0x71f 0x90     # байт 3             ┘
alc-verb 0x17 0x701 0x01     # выбор источника → ЦАП 0x03
alc-verb 0x17 0x707 0x40     # разрешить выход на пине
alc-verb 0x17 0x300 0xb000   # снять приглушение усилителя
```

**4. Закрепить** через [`scripts/woofer.sh`](../../scripts/woofer.sh) и
[`scripts/com.local.woofer.plist`](../../scripts/com.local.woofer.plist):

```bash
sudo cp scripts/woofer.sh /usr/local/bin/
sudo chmod 755 /usr/local/bin/woofer.sh
sudo cp scripts/com.local.woofer.plist /Library/LaunchDaemons/
sudo chown root:wheel /Library/LaunchDaemons/com.local.woofer.plist
sudo launchctl bootstrap system /Library/LaunchDaemons/com.local.woofer.plist
```

Демон дожидается запуска звука, применяет команды и повторяет их, если кодек сбросился — а это происходит
после пробуждения и при смене устройства вывода.

## Кроссовер существует — и он уже работает

У пути динамиков в AppleHDA есть *программная цепочка DSP*, описанная в файле раскладки AppleALC. Для
раскладки 13 цепочка встроенных динамиков содержит ровно одну функцию:

```
IntSpeaker → SignalProcessing → SoftwareDSP → DspFunction0
    DspFuncName: DspCrossover2Way
```

Двухполосный кроссовер. Он берёт стерео и делит его по частоте, а карта путей показывает, куда идут половины:

```
0x14 → ЦАП 0x02 [ch1, ch2]      верхняя полоса → верхняя пара
0x17 → ЦАП 0x03 [ch5, ch6]      нижняя полоса  → нижняя пара
```

Привязки `ch5/ch6` — вовсе не неиспользованный многоканальный остаток, каким они выглядели. Это
низкочастотный выход кроссовера. CoreAudio остаётся двухканальным устройством, потому что разделение
происходит **внутри драйвера**, и проверка доступных форматов потока была не тем тестом.

Подтверждено, что он именно работает, а не просто объявлен:

```bash
ioreg -l -w0 | grep -oE '"Dsp[A-Za-z0-9]+"=[0-9]+' | grep -v '=0$'
```

```
"DspFunc2WayCrossover" = 1      ← один живой экземпляр
"DspFuncEQ"            = 2      ← эти два заняты микрофоном и линейным входом
"DspFuncGain"          = 2
"DspParameter"         = 56
"DspPatchPoint"        = 24
```

Кроссовер оживает, как только задана pin-конфигурация узла `0x17`: до этого AppleHDA отбрасывает нижний путь,
и делить нечего. То есть правка pin-конфигурации выше делает больше, чем просто включает нижние динамики — она
достраивает правильно разделённую двухполосную систему, которая и была задумана в раскладке.

### Что это значит для тон-контроля

Значит **не пользоваться им.** Сдвиг уровня между парами расстраивает систему, которая уже разделена верно, —
ровно это и было слышно: −6 дБ верхней паре нормально звучали на басовитом материале и давали слышимые провалы
на плотном роке. `SPREAD=0` — не нейтральный компромисс, а правильная настройка.

### Эквалайзер внутри драйвера

Оба экземпляра `DspFuncEQ` принадлежат входным цепочкам. У цепочки динамиков был кроссовер и больше ничего —
ни эквализации, ни каскада усиления. Этот пробел закрыт.

Функция `DspEqualization32` в цепочке `IntSpeaker` даёт **32-полосный эквалайзер внутри драйвера**:
системный, действующий на любое приложение, без виртуального аудиоустройства и без вмешательства в клавиши
громкости. Цепочка стала такой:

```
IntSpeaker -> SoftwareDSP
    DspFunction0: DspEqualization32   экземпляр 0, индекс 0     <- добавлено
    DspFunction1: DspCrossover2Way    экземпляр 1, индекс 1
```

то есть эквализация происходит **до** того, как кроссовер разделит полосы, — и это правильный порядок:
обрез снизу защищает низкочастотники, а вырез на 2 кГц достаётся твитерам уже после разделения.

Раскладка — скомпилированный ресурс, поэтому нужна пересборка AppleALC. **Xcode для этого не нужен**,
вопреки тому, что говорила прежняя версия этого текста: достаточно Command Line Tools и MacKernelSDK,
сборка занимает около минуты, а весь рецепт — вместе с четырьмя ловушками, из-за которых сборка руками не
работает — в [Сборке AppleALC без Xcode](building-applealc-without-xcode.md). Патч и скрипт лежат в
[`tools/applealc-speaker-eq/`](../../tools/applealc-speaker-eq/), там же
[кодировка фильтров](../../tools/applealc-speaker-eq/README.md#the-filter-format), которая не описана больше
нигде.

Подтверждение, что эквалайзер создан, а не просто объявлен:

```bash
ioreg -l -w0 | grep -oE '"Dsp[A-Za-z0-9]+"=[0-9]+' | grep -v '=0$'
```

```
"DspFuncEQ"            = 3      <- было 2 (микрофон и линейный вход), третий наш
"DspParameter"         = 60     <- было 56
"DspFunc2WayCrossover" = 1      <- без изменений
```

**Теперь это подтверждено измерением, а не только слухом.** Запись одного и того же сигнала
с эквалайзером и со штатным AppleALC, с одной и той же точки микрофона, и вычитание одного из другого
убирают и собственную характеристику микрофона, и большую часть интерференции. Остаётся то, что сделал
эквалайзер:

```
средний промах 0,7 дБ, худший 2,2 дБ      при повторяемости стенда ±1,5 дБ
```

Значит драйвер применяет задуманную кривую точно. Выбрать правильную кривую — задача сложнее, она разобрана
в разделе [к чему стремиться](#эквалайзер-к-чему-стремиться) — включая одну полосу, которую измерение
признало ошибочной. Сам метод и четыре способа обмануться при анализе — в
[tools/measure](../../tools/measure/README.md).

## Почему ЦАП 0x03 и почему демон

Узел `0x17` можно питать от ЦАП `0x02`, `0x03` или `0x06`. На `0x02` сидят твитеры.

`0x02` и `0x03` несут один и тот же поток, и **macOS двигает их громкость синхронно** — проверено:

```
громкость 30%:  0x02 = 0x30   0x03 = 0x30
громкость 90%:  0x02 = 0x53   0x03 = 0x53
```

Если посадить низкочастотные на `0x03`, их уровень можно держать *выше* твитеров на постоянную величину —
получается настоящий аппаратный подъём низов, который при этом следует за регулятором громкости. Разовая
правка усиления слетела бы при первом же его изменении, поэтому и нужен демон, который держит

```
усиление(0x03) = min( система, CAP )
усиление(0x02) = max( усиление(0x03) − SPREAD, FLOOR )
```

Все три величины — в начале `woofer.sh`. Почему в итоге осталась одна ручка — см.
[Одна ручка, а не две](#одна-ручка-а-не-две).

Усилители на пинах у этого кодека **только с приглушением** (`AMP-OUT cap = 0x80000000`), вся регулировка
громкости — на ЦАП. Не тратьте время на попытки выставить уровень самому `0x17`. У ЦАП 87 шагов по
0,75 дБ, максимум `0x57`.

## Измерения

Мерялось **внешним микрофоном** — Logitech C930e на штативе в 10 см от ноутбука, запись на отдельной машине
через ffmpeg, разбор фильтром Гёрцеля на частоте тона. Шум помещения во время замеров: −98,4 дБ RMS.

> **В предыдущей версии этого документа были другие цифры, снятые встроенным микрофоном ноутбука. Они
> оказались неверными и заменены.** Встроенный микрофон стоит в корпусе и ловит вибрацию через шасси, поэтому
> его показания сильно зависят от того, на чём стоит ноутбук, — и он придумывал искажения, которых нет.
> Характеризовать эти динамики встроенным микрофоном нельзя.

**Только твитеры:**

| Тон | Уровень | Искажения |
|---|---|---|
| 1 кГц | **−40,4 дБ** | 0,6 % |
| 200 Гц | **−127,5 дБ** | — (ниже уровня шума) |

На 200 Гц твитеры не выдают *ничего* — на 87 дБ ниже собственного уровня на 1 кГц и ниже шума помещения.
«Басов нет» — это буквальная констатация. На 1 кГц они при этом чистые: 0,6 % искажений.

**Только низкочастотные, 200 Гц, перебор усиления ЦАП:**

| Усиление ЦАП | Уровень | Искажения |
|---|---|---|
| `0x41` | −42,8 дБ | 1,1 % |
| `0x48` | **−29,4 дБ** | 2,4 % |
| `0x4e` | −29,3 дБ | 2,7 % |
| `0x52` | −29,0 дБ | 2,6 % |
| `0x55` | −29,5 дБ | 2,7 % |
| `0x57` (максимум) | −29,3 дБ | 2,8 % |

Отсюда два следствия. Против −127,5 дБ у твитеров низкочастотные дают −29 дБ на той же частоте — то есть
**примерно на 98 дБ больше на 200 Гц**. И уровень **насыщается уже на `0x48`**: всё, что выше, совпадает в
пределах погрешности, так что дальнейшее усиление здесь ничего не добавляет.

**Только низкочастотные, 120 Гц:**

| Усиление ЦАП | Уровень | Искажения |
|---|---|---|
| `0x4e` | −45,3 дБ | 14,2 % |
| `0x52` | −43,6 дБ | 9,2 % |
| `0x55` | −42,5 дБ | 12,2 % |
| `0x57` (максимум) | −39,9 дБ | **57,2 %** |

Ниже по частоте запас по уровню ещё есть, но там же и обрыв: на максимуме кодека третья гармоника доходит до
−44,7 дБ, а искажения до 57 %. Это динамик уходит в отбой, и на слух это дребезжание.

`CAP=0x52` вытекает из этих двух таблиц: на 200 Гц выход к этому моменту уже насыщен, а на 120 Гц это точка с
наименьшими искажениями из измеренных.

## Тон-контроль в железе

Своего эквалайзера в macOS нет, но у этой машины есть кое-что почти столь же полезное: **два независимых
усиления ЦАП, питающих две пары динамиков с очень разными характеристиками.**

| | Узел 0x14 → ЦАП 0x02 | Узел 0x17 → ЦАП 0x03 |
|---|---|---|
| ниже 200 Гц | ничего | работает от ~120 Гц |
| 500 Гц | −42 дБ | **−20 дБ** |
| 2 кГц | **−16,5 дБ** | −23 дБ |
| 4 кГц | −36 дБ | −28 дБ |

Верхняя пара несёт пик на 2 кГц — ту самую резкость — и снизу не даёт ничего. Нижняя закрывает 120 Гц – 1 кГц.
Значит *изменение их соотношения и есть тон-контроль*, причём без всякого софта.

Этим занимается [`scripts/woofer.sh`](../../scripts/woofer.sh):

```
усиление(0x03) = min( система, CAP )                     # нижняя пара
усиление(0x02) = max( усиление(0x03) − SPREAD, FLOOR )   # верхняя пара
```

По умолчанию: `SPREAD=0` (нейтрально — см. ниже), `CAP=0x52`, `FLOOR=0x20`.

**Почему `CAP=0x52`.** На 200 Гц нижняя пара насыщается уже к `0x48` — измерено, всё выше совпадает в
пределах погрешности, — а из измеренных точек на 120 Гц `0x52` оказалась наименее искажённой. Поднимать дальше значит не добавить низа, а раздуть 300 Гц – 1 кГц, то есть коробочность. Поэтому
потолок ограничивает **подъём** и никогда не опускает ниже системного уровня: на большой громкости нижняя пара
просто следует за регулятором, потому что динамик и так на пределе.

**Почему `SPREAD` небольшой.** Приглушение верхней пары бьёт точно в пик 2 кГц: 12 шагов роняют его на 4,6 дБ,
а 500 Гц всего на 1,1 — потому что 500 Гц отдаёт *другая* пара. Но вместе с пиком уходит и 4 кГц: на 12 шагах
верх просел на 6,7 дБ и звук стал заметно глуше. Восемь шагов выбраны на слух: четыре почти не слышно, двенадцать глухо. Приборно к тому моменту предел был исчерпан — замер с одной позиции микрофона не различает последние децибелы, так что итоговое значение это решение на слух, а не измеренное.

Чего так не сделать — обреза ниже 110 Гц и полки выше 4,5 кГц, для них нужен настоящий эквалайзер. Два пункта
из пяти закрыты железом, остальное — софтом, если захотите.

### Как подстроить на слух

Три числа в начале `scripts/woofer.sh`. Скажу честно: приборно я довёл это до предела возможного — замер с
одной позиции микрофона не различает последние децибелы, а абсолютные уровни между сеансами несопоставимы.
Дальше это вкус.

| Изменение | Что даёт |
|---|---|
| `SPREAD` больше | больше баса и меньше резкости на 2 кГц, но меньше воздуха на 4 кГц. Дальше ~12 шагов звук глохнет |
| `CAP` меньше | берёжет нижнюю пару на большой громкости, но и общая громкость там ниже |

После правки:

```bash
sudo cp scripts/woofer.sh /usr/local/bin/
sudo launchctl kickstart -k system/com.local.woofer
```

Изменения вступают в силу секунд через тридцать и только после того, как тронете регулятор громкости — демон
срабатывает в момент, когда macOS выставляет оба ЦАП в одно значение.

### Честный итог: нейтраль

`SPREAD` по умолчанию **0**, и это результат, а не лень.

Восемь шагов (−6 дБ верхней паре) хорошо звучат на хип-хопе, где энергия внизу. На плотном роке — нет:
проверяли на Linkin Park, *Numb*, и появлялись слышимые провалы. Середина и верх 2–8 кГц идут именно с верхней
пары, и любое её приглушение их выедает. На нуле звучит правильно.

Причина в том единственном, что здесь не поправить: **обе пары получают полнополосный сигнал, без кроссовера.**
Перекладывать уровень между ними — компромисс, а не решение. Поднимешь низкочастотные — раздувается 300 Гц –
1 кГц; приглушишь верхние — худеет верхняя середина. Настройки, верной для любого материала, не существует, и
ровно это решил бы кроссовер.

Поэтому демон поставляется нейтральным. При `SPREAD=0` у него остаётся одна работа — восстановить
pin-конфигурацию узла `0x17`, если кодек её сбросит. Это страховка: при загрузке её и так задаёт `ConfigData`.

Если баса всё же хочется: 2–4 шага терпимо, 8 слышно на роке, 12 стоит 6,7 дБ на 4 кГц (измерено). Это ручка
вкуса, а измерения выше говорят, сколько стоит каждый шаг.

### Одна ручка, а не две

В более ранней версии их было две: подъём нижней пары и приглушение верхней. Они складываются, и результат
зависел от громкости так, что звучало неправильно: на 40 % разброс доходил до 18 дБ и бас гудел, а на 85 %
подъём упирался в потолок и не применялся вовсе, оставляя ровные 6 дБ. Получалось, что громко машина звучит
лучше, чем тихо, — для регулятора тембра это наизнанку.

Поэтому теперь один параметр, `SPREAD`, и он держит одинаковое расстояние между парами на любой громкости:

```
усиление(0x03) = min(система, CAP)          # нижняя пара, никогда не выше регулятора
усиление(0x02) = max(усиление(0x03) − SPREAD, FLOOR)
```

Верхняя пара привязана к **нижней**, а не к регулятору. Иначе на 100 % нижняя упирается в `CAP`, верхняя
продолжает расти, и разброс падает с 6 дБ до 2 — тембр менялся бы на максимуме. Проверено: +6,0 дБ на 25,
40, 55, 70, 85 и 100 %.

### Чтение усиления ЦАП не всегда надёжно

`alc-verb 0x02 0xb 0x8000` иногда возвращает `0x00000000`, хотя звук очевидно играет на уровне регулятора.
Поэтому демон действует только когда **оба** ЦАП читаются одинаково — это признак того, что значение только что
выставила macOS по регулятору, — и не трогает ничего ниже `FLOOR`.

Более ранняя версия вычисляла «системную громкость» из тех же регистров, в которые сама и писала. Это
замкнутый круг: на первом же неверном чтении она загнала оба усиления в ноль и лишила машину звука. Если будете
переделывать скрипт, эту защиту оставьте.

## Эквалайзер: к чему стремиться

Кроссовер оказался настоящим и уже работающим (выше), так что осталась эквализация. Настройки ниже не
выдуманы — они выведены из измеренной характеристики, и это та самая кривая, что теперь стоит в драйвере.

Суммарная характеристика обеих пар при одинаковом усилении, относительно среднего на 500 Гц – 1 кГц:

| Гц | относительно |
|---|---|
| 120 | **−31 дБ** |
| 160 | −21 дБ |
| 200 | −10 дБ |
| 300 | −2 дБ |
| 500 | +2 дБ |
| 800 | −1 дБ |
| 1000 | −0,5 дБ |
| 2000 | **+5 дБ** |
| 4000 | −6 дБ |

Ниже 120 Гц нет вообще ничего, от 300 Гц до 1 кГц широкое плато, на 2 кГц заметный пик, выше — спад.

**Цель, после нормального измерения:**

Таблица, которая стояла здесь раньше, выведена с одной позиции микрофона, и одна её строка оказалась
неверной. Три позиции, усреднённые по мощности, дают вот такую характеристику самих динамиков относительно
800–1250 Гц. Колонка **разброс** — это расхождение между позициями, и именно она решает, что вообще
позволено править эквалайзером:

| Гц | отн. дБ | разброс | что это значит |
|---|---|---|---|
| 200 | −19,6 | 6,5 | низа действительно нет |
| 250 | −10,6 | 6,4 | |
| 315 | −4,8 | 6,9 | |
| **400** | **+0,4** | 6,5 | локальный максимум |
| **500** | **−4,9** | 10,6 | **провал, а не пик** |
| **630** | **−10,8** | **3,1** | глубокий, и *одинаковый во всех позициях* |
| 1250 | +3,0 | 12,9 | |
| 1600 | +3,4 | 8,6 | |
| **2000** | **+6,5** | 6,2 | пик реален |
| 2500 | +1,2 | 5,0 | |

**Исправление.** Прежняя версия резала 500 Гц на 3 дБ, называя это «собственным пиком нижней пары, от
которого коробочность». Усреднение показывает там **провал −4,9 дБ**. Мы углубляли яму. Эта полоса убрана.

**Находка.** У провала на 630 Гц **самый маленький разброс во всей таблице**. Всё остальное гуляет на
6–13 дБ при сдвиге микрофона, а он — нет. Это признак настоящего свойства системы, а не интерференции в
комнате; и на такой частоте в двухполосной системе очевидный подозреваемый — фазовое гашение в зоне стыка
кроссовера. Фазовую проблему уровнем не лечат, поэтому провал засыпан лишь частично.

Итоговая кривая, которая сейчас стоит в драйвере:

| Что | Где | Насколько | Зачем |
|---|---|---|---|
| Обрез снизу | 110 Гц, Q 0,71 | — | Ниже только ход диффузора и грязь. |
| Подъём | 170 Гц, Q 0,9 | **+8 дБ** | Самая низкая область, где нижняя пара ещё отзывается. |
| Засыпка | 630 Гц, Q 2,0 | **+4 дБ** | Частичная, по причине выше. |
| Срез | 1800 Гц, Q 1,0 | **−7 дБ** | Подъём 1,25–2 кГц — самая надёжно измеренная деталь. |
| Подъём | 7000 Гц, Q 0,7 | **+4 дБ** | Верх. **Не проверено** — см. оговорку ниже. |
| Обрез сверху | 19 кГц, Q 0,71 | — | |

Взвешенное отклонение в полосе 250 Гц – 2,5 кГц: **5,9 дБ без эквалайзера, 4,4 дБ со старой кривой,
3,0 дБ с этой.** Старая кривая помогала куда меньше, чем казалось, — ошибочный срез 500 Гц работал против
всего остального.

**Чего исправить нельзя, и почему «добавить ещё эквалайзера» — неверный ответ:**

- **200 Гц остаётся на −11 дБ.** Динамик на пределе. Подъём +8 дБ уже поднял искажения на 200 Гц с 2,1 % до
  3,9 %. Перебор параметров кривой нашёл, что +9 дБ «лучше» на бумаге; на деле это покупает искажения, а не
  громкость.
- **630 Гц остаётся на −6 дБ.** См. выше: это фаза, а не уровень.

**Верх не измерен.** Выше 3 кГц этот стенд расходится на 4–7 дБ *между двумя замерами, когда ничего не
трогали*. Поэтому +4 дБ на 7 кГц унаследованы от прежней работы с одной позицией и намеренно оставлены без
изменений: доказательств менять их в любую сторону нет. Если у вас есть настоящий измерительный микрофон —
начинать надо именно отсюда.

Своего системного эквалайзера в macOS нет. Путь, выбранный здесь, кладёт эту кривую **внутрь драйвера** —

см. [эквалайзер внутри драйвера](#эквалайзер-внутри-драйвера) — это стоит пересборки AppleALC, зато в
пользовательской части не работает ничего. Если пересобирать не хочется, из бесплатных обычно берут
[eqMac](https://eqmac.app), из платных SoundSource; и та и другая ставят виртуальное аудиоустройство, которое
становится выводом по умолчанию, так что делать это стоит тогда, когда рабочий звук не нужен через пять
минут.

Считайте это отправной точкой и правьте на слух. Замер снят с одной позиции микрофона в 10 см, поэтому
тонкая структура — точная высота пика на 2 кГц, провал на 4 кГц — отчасти отражения от корпуса и стола, а не
чистая характеристика динамика. Широкая форма надёжна, отдельные децибелы — нет.

## Оговорки

- Динамики маленькие. Это даёт реальную нижнюю середину в районе 120–250 Гц, но не глубокий бас. На 70 Гц
  намерять не удалось ничего.
- `alcverbs=1` должен остаться в boot-args, иначе демон молча не сделает ничего.
- Демон опрашивает кодек раз в 3 секунды — это дёшево, но означает небольшую задержку после изменения
  громкости.
- Ручная отправка команд усиления может рассинхронизировать представление macOS о громкости с кодеком:
  регулятор показывает 85 %, а ЦАП стоит на нуле. Лечится любым движением регулятора. Возникает только после
  ручных экспериментов, в обычной работе — нет.

## Утилиты для измерений

`tools/rec.swift` пишет звук со входа по умолчанию в WAV; `tools/measure-thd.py` показывает уровень основного
тона и его второй и третьей гармоник.

**Лучше внешний микрофон на второй машине.** Встроенный здесь непригоден по причинам выше. Схема, которой
получены цифры этого документа: тоновые файлы на маке проигрываются через `afplay` по SSH, запись на машине с
Windows командой

```
ffmpeg -f dshow -i audio="Microphone (...)" -t 5 -ac 1 -ar 48000 -y out.wav
```

и разбор через `tools/measure-thd.py`. Ноутбук и микрофон между прогонами не двигать, иначе абсолютные уровни
несопоставимы.

Если всё же берёте встроенный микрофон: **процесс, запущенный через SSH, до него не доберётся.** macOS
откажет молча и отдаст файл из одних нулей, не показав запроса. Запускайте из графической сессии —
`open -a Terminal /путь/к/скрипту.command` вызывает запрос разрешения как положено.
